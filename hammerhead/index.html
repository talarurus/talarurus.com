SEVEN EXISTING CHECKS

Concrete observations.
Useful context.

Security, Hygiene, and Info findings stay separate. Only Security findings affect the finding threshold. Patterns indicate things to review; they do not establish compromise.

Checks in 0.2.0-dev
RuleChecks forClass
FILE-001Potential sensitive files by filenameSecurity

GET STARTED

One command.
A useful report.

Build 0.2.0-dev from the pinned development commit for controlled testing. Full untrusted-repository security qualification and release CI are still pending. Start with a synthetic fixture and review the limitations.

Preview and download status →

Verify the build

hammerhead version

Audit the current repository

hammerhead audit .

Write a JSON report

hammerhead audit ./demo-repository --output json > ./audit.json

Keep reports outside the audited directory. Exit 1 means a completed scan reached the Security threshold; incomplete scans and output failures exit 2, even with --fail-on none.

THE SECURITY MODEL

Clear boundaries.
Honest expectations.

SafeWalker uses guarded reads and symlink containment checks. These are defense-in-depth measures, not a sandbox or a guarantee of safety.

Read the security model ↗
What the preview inspects

The current working tree, supported sensitive filenames and credential patterns, repository hygiene, and project context.

What it does not do

It does not scan Git history, validate active credentials, provide CVE database scanning, or perform semantic SAST analysis.

Coverage and limits

Read status, policy, per-check coverage, and diagnostics with every report. Completed means within the declared scope. Partial, failed, and cancelled scans exit 2. Exit 0 does not establish safety.
