Checksums and verification

No release checksum manifest or signature is offered for this preview. An eventual release must identify its exact version and source commit, publish a SHA-256 manifest for the actual archives, and document the authenticity checks that are available. Checksums detect byte differences; they do not independently establish publisher identity.

Installation after a qualified release

  1. Select the exact versioned archive for the operating system and architecture.
  2. Verify its SHA-256 against the published manifest using shasum -a 256 on macOS or sha256sum on Linux. Complete any documented signature/authenticity checks before running it.
  3. Extract the verified archive into a new directory, review its included instructions, and place the executable in a user-owned directory on PATH.
  4. Run hammerhead version, compare the version and commit to the release notes, then test a controlled fixture.

These are future release steps. For the current preview, use the commit-pinned self-build guide.
